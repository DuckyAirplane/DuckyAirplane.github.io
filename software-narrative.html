Travlr Getaways Enhancement Narrative

The artifact I selected is the Travlr travel application from CS 465 Full Stack Development. It uses Node.js and Express for the server, MongoDB and Mongoose for the database, and Angular for the administrative side. The application also includes an API and authentication for protected changes.

I chose Travlr because it gave me a good project to improve without starting over. The original application worked, but there were problems with validation, error handling, and security that I wanted to fix.

I started by improving the trip model. I added validation for blank values, text length, and start dates. I also updated the trip controller so invalid requests return clearer error messages instead of raw database errors. Updates now use the same validation rules as newly created trips.

I also improved the JWT authentication. The original project had a fallback secret written directly in the code. I removed that and moved the JWT secret into a protected environment file. I also updated the authentication middleware so missing, malformed, expired, and invalid tokens are handled correctly.

I tested these changes by creating a temporary account, generating a JWT, and sending different requests to the API. Invalid trip data returned a 400 response, and incorrectly formatted authentication returned a 401 response. One issue I ran into was testing against an older version of the running server. Restarting it loaded the updated code and fixed the problem.

This enhancement helped me work with validation, API error handling, authentication, testing, and secure configuration. It also supports Course Outcomes 3, 4, and 5 because I improved an existing application, used established development practices, and addressed security problems in the original code.

The enhanced version of Travlr handles bad data better, gives clearer API responses, validates updates, and keeps the JWT secret out of the source code. These changes made the project more reliable and secure.

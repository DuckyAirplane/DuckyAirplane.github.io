Travlr Getaways Database Enhancement Narrative

The artifact I selected is the Travlr Getaways application from CS 465. It stores travel packages in MongoDB and uses Mongoose and an Express API to work with the trip data.

I chose Travlr for this enhancement because there were several ways I could improve how the application stored, searched, and protected its data.

I started by adding unique trip codes, timestamps, sorting, pagination, filtering, and a start-date index. I also updated the controller so bad requests were handled more clearly.

While testing the date filter, I found that some older trip dates were stored as text instead of real dates. I checked the records and created a small script to convert the older values. After that, the date filter worked correctly.

I also found a problem with duplicate trip codes. Even though the schema marked the code as unique, MongoDB was still using an older non-unique index. I created a script to remove the old index and rebuild it correctly. After the fix, duplicate trip codes returned a 409 Conflict instead of being added to the database.

I added an aggregation endpoint that groups trips by resort and returns the number of trips and earliest start date for each resort. I also added audit logging for CREATE, UPDATE, and DELETE actions. Each audit record stores the trip ID, trip code, action, and timestamps.

I tested the database changes with Postman and checked MongoDB directly to make sure the data and audit records were being saved correctly.

This enhancement gave me more experience with MongoDB, Mongoose, indexes, migrations, filtering, aggregation, API testing, and data validation. It also supports the course outcomes involving evaluating computing solutions, using established development tools, and protecting data.

The biggest problems I ran into came from existing data and database indexes rather than the code itself. Fixing those problems gave me more experience checking the actual database instead of assuming a code change automatically changed existing stored data.
